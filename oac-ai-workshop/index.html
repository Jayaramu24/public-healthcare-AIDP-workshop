Lab 0 Get ready for the MPHA workshop

In this three-hour workshop, experienced analysts use Oracle Analytics Cloud AI features to investigate MPHA healthcare claims. You will prepare metadata, build and validate visualizations, create a rollup data flow, compare narratives with the numbers that support them, and use Claude MCP to discover data and build an HTML overview with a native OAC recreation. MPHA is the synthetic healthcare scenario in the existing workshop kit.

Updated 20 October 2026: seven AI capabilities have now been exercised successfully. Lab 7 is a 15-minute instructor demonstration in Industry Analytics using the saved MPHA_Claims_Semantic_Demo model and semmodel connection. The seven other AI feature labs remain hands-on in the original workshop OAC environment. Lab 9 adds a Claude Free MCP demonstration with optional preconfigured participant clients and dashboard validation. Expression Assistant generation still uses its validated manual fallback. Participant access, an active workshop instance and a second-account rehearsal remain event readiness gates.

Objectives

  • Use ClaimStar_KJ through your own workshop dataset copy.
  • Check AI outputs against known claims totals and aggregation rules.
  • Finish with an individual workbook and a district-month rollup.
  • Recognize the difference between generated metadata, calculated metrics, and a semantic model.

Lab 1 Prepare a dataset with Dataset Assistant

You will create an individual copy, inspect suggested column names, and decide whether suggested attribute and measure types fit the claims model. The source already has friendly names, so reviewing a suggestion is a valid result.

Task 1 Create your dataset copy

  1. On the dataset card, open Actions and select Open. Wait for permission checking to finish before choosing an action.
  2. In the transform editor, open the arrow beside Save Dataset and select Save As. During rehearsal this succeeded when the Home Duplicate action returned a server error.
  3. Enter ClaimStar_Pxx. Save in My Folders or a participant folder assigned by the facilitator. Click OK, wait for completion, and verify the editor heading uses your new name.
  4. Confirm 20 data elements are present. The left Preparation Script already contains renames and the Processing Days Total Approx helper. Reuse these prepared steps.

Task 2 Generate and review column names

  1. In the transform editor, click the Magic Wand icon. This opens Dataset Assistant Table Recommendations.
  2. Keep the Column Rename tab selected. Inspect Case and Replace, then click Generate Column Names.
  3. Compare Current and New. In rehearsal the assistant suggested Approximate Total Processing Days for Processing Days Total Approx. Existing friendly names mostly stayed the same.
  4. For the core exercise, keep the existing names so later prompts match this guide. Close the recommendations without applying the rename. In your own copy you may apply a chosen rename, but then adapt every subsequent prompt and expression.

Task 3 Review Treat As suggestions

  1. Reopen Magic Wand if necessary and choose Treat As.
  2. Inspect the four claim count fields. Rehearsal suggested changing Claims Submitted, Approved Claims, Denied Claims, and Pending Claims from measures to attributes.
  3. Reject that suggestion for this reporting model: these counts must remain additive measures with Sum aggregation. Close the recommendation panel.
  4. Use Metadata view to confirm the counts and monetary totals are measures. Keep Average Processing Days and Denial Rate as non-additive attributes. Save your dataset if you made an intentional correction.

Checkpoint

Your own dataset opens with 20 data elements. Claims counts remain Sum measures. You can explain why a plausible AI recommendation can be unsuitable for the business model.

Lab 5 Validate a denial-rate calculation

You will request an aggregate expression, inspect it, and validate the denominator logic. In this tenant, Expression Assistant returned a generation error in rehearsal, including after explicit dataset selection and simpler prompts. The manual route below was validated and produced the expected 8.64% KPI.

Task 1 Try Expression Assistant

  1. In the workbook Data panel, open its Menu and select Create Calculation.
  2. Name the calculation Claims Denial Rate Workshop. If several datasets are present, choose your intended dataset using Pick dataset beside the Assistant input.
  3. Enter the prompt below in the Assistant box and press Enter. Allow the request to finish.
  4. If generation succeeds, inspect the entire expression. If OAC displays the captured generation error, move to Task 2 after one retry. Do not spend the whole timebox retrying.
Calculate the ratio of total Denied Claims to total Claims Submitted. Return NULL when total Claims Submitted is zero. Use a ratio from 0 to 1, not multiplied by 100.

Task 2 Use and validate the fallback

  1. Create the formula below in the Expression editor. Insert each field from Data Elements, or use autocomplete if shown; the field references must be fully qualified.
  2. If you need to construct the reference explicitly, open your dataset Actions → Inspect → General in a second tab and copy Object ID. It contains the namespace and dataset name. In the supplied formula file replace the entire rehearsal object ID with your own copied ID, keeping XSA(...), the table MPHA_OAC_STAR_CLAIMS, and the field names.
  3. Do not paste bare field names such as SUM("Denied Claims"). OAC rejected that form because the dataset and table paths were missing.
  4. Click Validate. Continue only when OAC reports Calculation validated, then click Save.
  5. Recovery: Save As the prepared workbook as Claims_AI_Pxx. Its existing calculation refers to the prepared base dataset and already produces 8.64%. Do not change its object ID unless you also replace its data source.
CASE WHEN SUM(<Claims Submitted token>) = 0 THEN NULL
ELSE 1.0 * SUM(<Denied Claims token>) / SUM(<Claims Submitted token>) END

Task 3 Create the KPI

  1. Under My Calculations, right-click Claims Denial Rate Workshop and select Create Best Visualization.
  2. Select the new tile. Open Properties, then Values, expand the calculation, and change Value from Auto to Percent. Keep two decimal places.
  3. Confirm the total displays 8.64%. This is 121 divided by 1,400, formatted as a percentage once.
  4. Save Claims_AI_Pxx. Optionally repeat the calculation using SUM(Processing Days Total Approx) divided by SUM(Claims Submitted), guarded for zero. Label it Weighted Processing Days Approx; the expected total is approximately 13.59 days.

Checkpoint

The calculation is validated and the tile displays 8.64%. Changing to district grain must recompute the ratio of totals. Never use SUM(Denial Rate).

Lab 6 Build and run a rollup with Data Flow Assistant

You will turn 622 claims segments into 30 district-month rows and recompute ratios after aggregation. The prepared MPHA_Claims_Rollup_Flow_Seed completed in 22 seconds in this rehearsal. That is an observation from one run, not a concurrency or response-time guarantee.

Task 1 Create the flow and input

  1. At Home, choose Create, then Data Flow. Select your ClaimStar_Pxx dataset and click Add.
  2. Save the draft as Claims_Rollup_Flow_Pxx in your own folder.
  3. Open Assistant on the flow toolbar. If it is absent, the facilitator must enable both Data Flow AI preview switches before the event. After activation, allow time for propagation and refresh the saved flow.
  4. Keep one participant’s flow per name. Do not edit the shared seed or run all 20 flows simultaneously.

Task 2 Generate the aggregation

Aggregate the data by Service Month and District Name. Sum Claims Submitted, Approved Claims, Denied Claims, Pending Claims, Total Paid Amount, and Processing Days Total Approx. Exclude other columns.
  1. Enter the prompt in Assistant and press Enter. In rehearsal the Assistant added an Aggregate step directly to the flow.
  2. Select Aggregate and verify exactly two grouping fields: Service Month and District Name.
  3. Verify exactly six aggregate fields and that every function is Sum. The output names in rehearsal end with Sum, as shown.
  4. Check the preview. Do not aggregate Denial Rate or Average Processing Days. If the Assistant makes a different selection, correct it before continuing.

Task 3 Generate derived fields after aggregation

Add two columns: Claims Denial Ratio equals Denied Claims Sum divided by Claims Submitted Sum. Weighted Processing Days Approx equals Processing Days Total Approx Sum divided by Claims Submitted Sum. For both columns return null when Claims Submitted Sum is zero. Keep all existing columns.
  1. Submit the derived-fields prompt. Select the generated Add Columns node.
  2. Inspect Claims Denial Ratio. The tested expression uses Denied Claims Sum / NULLIF(Claims Submitted Sum, 0).
  3. Inspect Weighted Processing Days Approx. The tested expression uses Processing Days Total Approx Sum / NULLIF(Claims Submitted Sum, 0).
  4. Confirm both expressions use aggregated output columns and protect zero denominators. Keep the existing eight rollup columns as well as the two new ones.

Task 4 Save the output and execute

Save the result to a new Oracle Analytics dataset named Claims_Rollup_Pxx.
  1. Submit the output prompt using your participant ID. Inspect Save Data: Save data to must be Dataset Storage for this exercise.
  2. Verify the output name is unique and click Save on the flow toolbar. This saves the flow definition.
  3. When the facilitator calls your wave, click Run Data Flow once. Saving the definition alone does not create the output.
  4. Open the flow Page Menu, Inspect, then History. Wait for Completed. If a run fails, open its details before retrying; do not repeatedly submit it.

Task 5 Reconcile the output

  1. At Home, locate your output dataset and select Open. Confirm it has 30 rows and 10 columns.
  2. Check the six totals against Lab 0. The supplied checkpoints/MPHA_Claims_Rollup_Seed.csv was downloaded from the completed OAC output and independently reconciled.
  3. Check one row: January, Central City has 66 submitted, 58 approved, 5 denied, 3 pending, 43,829.42 paid, and 908.6 approximate processing-days numerator.
  4. For that row, confirm 5/66 = 0.075757… and 908.6/66 = 13.766666… . Do not sum or average the 30 output ratios for an overall KPI; recompute from the six summed measures.
